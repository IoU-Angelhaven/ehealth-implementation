## Checklist

- Review everything you have learned so far: approval, user research, process maps, stakeholder input and comparisons with others.
- Write a clear problem statement: who is affected, what the problem is and why it matters.
- Make sure the statement describes the problem, not a solution or a technology.
- Check the statement with end users, clinical staff and key stakeholders.
- Make it specific enough to guide decisions, but not so narrow that it rules out good solutions.
- Get approval from the project sponsor or decision-makers.
- Use the statement as a reference during the whole project to avoid adding work that does not belong.

## Methods and tools

- **[“How might we…?” questions](https://www.designkit.org/methods/how-might-we.html):** Turn the problem into open questions that invite ideas.
- **[Point of view statement](https://ixdf.org/literature/article/define-and-frame-your-design-challenge-by-creating-your-point-of-view-and-ask-how-might-we):** A one-sentence summary in the form “[User] needs [need] because [insight].”
- **[5 Whys](https://www.ihi.org/sites/default/files/SafetyToolkit_5Whys.pdf):** Ask “why?” again and again to find the root cause behind the surface problem.
