Make the evaluation plan before the pilot starts. A pilot is not early use by enthusiastic staff. It is a structured test that answers specific questions. A structured evaluation lowers risk and supports decisions based on evidence.

## Checklist

- Define the pilot: which departments, which patient groups, how many users and how long. Choose sites and users who are typical but manageable.
- Write the questions the pilot must answer. For example: Does the solution improve results? Does it fit the workflow? Are there unwanted effects?
- Set clear criteria for deciding whether to continue, adjust or stop.
- Choose a study design that fits the questions and the resources.
- Choose measures for how the solution is used and for the results. Combine numbers with interviews or observations ([mixed methods](https://catalyst.harvard.edu/community-engagement/mmr/)).
- Plan data collection: tools, schedule, responsibilities, and data security and privacy.
- Plan how problems will be found and fixed during the pilot, and when decisions will be made.
- Plan how results and lessons will be shared with participants and leaders.

## Methods and tools

- **[Pilot study](https://www.nccih.nih.gov/grants/pilot-studies-common-uses-and-misuses):** A small-scale test of the solution and the methods before a larger rollout.
- **[RE-AIM framework](https://www.re-aim.org/):** Structures the evaluation around Reach, Effectiveness, Adoption, Implementation and Maintenance.
- **[Mixed methods](https://catalyst.harvard.edu/community-engagement/mmr/):** Combines numbers (logs, surveys) with experiences (interviews, observations).
- **[Plan-Do-Study-Act (PDSA) cycles](https://www.ihi.org/library/model-for-improvement/testing-changes):** Short test cycles that allow quick learning and adjustment.
