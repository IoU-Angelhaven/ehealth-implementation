Early versions help the team find problems quickly, check assumptions and learn what works for users. Building and testing early versions several times lowers risk and gives solutions that fit users better.

## Checklist

- Choose which ideas to turn into early versions, based on priority and what you can learn.
- Decide how detailed the early version should be: a sketch, a simple screen drawing, a mockup or a working version.
- Choose the main user workflows to show, including the normal path and the main alternatives.
- Start with simple versions, such as paper sketches.
- Ask 5–8 possible users for quick feedback, and improve the version.
- Add more detail only when it is useful.
- Prepare the version for testing with a scenario and clear instructions.
- Write down design decisions and why features were included or left out.

## Methods and tools

- **[Sketches and paper prototypes](https://www.nngroup.com/articles/paper-prototyping/):** Simple paper versions that can be tested before anything is built.
- **[Simple and detailed prototypes](https://www.nngroup.com/articles/ux-prototype-hi-lo-fidelity/):** Explains the difference between a rough early version and a version that looks like the final product.
- **[Storyboards](https://www.nngroup.com/articles/storyboards-visualize-ideas/):** A series of pictures that shows how a user goes through a situation.
- **[Role-play walkthrough](https://servicedesigntools.org/tools/role-playing):** Staff act out the new process to find problems.
